# Каталог IstraArt из OLNOO

Источник: существующая таблица catalog_cards в OLNOO, проект istraart. Сайт не имеет собственной БД или админки. Демо-товары/цены удалены из каталога, декоративные изображения других секций сохранены.

Страница получает опубликованный whitelist DTO серверным запросом к /api/catalog/export. Ключ чтения OLNOO привязан только к istraart. Две серверные переменные для авторизации: OLNOO_CATALOG_TOKEN (отдельный ключ чтения проекта, минимум 32 символа) и OLNOO_CATALOG_BASIC_AUTH (существующее имя:пароль внешней Basic Auth Admin). OLNOO_CATALOG_URL — HTTPS origin Admin, по умолчанию https://admin.olnoo.com. Ни одна переменная не NEXT_PUBLIC, секреты не попадают в HTML/клиентские props/фото URL. Не отключать Basic Auth и не открывать внутренние API.

Фото выдаёт только серверный proxy сайта /api/catalog/photos/<cardUUID>/<originalIndex>. OLNOO на каждом запросе проверяет публикацию, проект ключа и то, что индекс используется опубликованным предложением. Нет произвольного upstream URL, доступа к оригинальным item id, путям uploads, черновикам или PDF. Данные и фото используют no-store; изменение цены/выбора фото обновляет ту же карточку при следующей загрузке страницы. Снятая с публикации карточка/фото перестают выдаваться; уже полученное посетителем публичное содержимое отозвать невозможно.

Новые Материал/raw, Готовое изделие/finished и Гайд/guide приходят самостоятельными карточками с собственными UUID и slug. Старые объединённые карточки сохраняют свои предложения. Отсутствующие предложения не получают выдуманной цены/наличия. В физическом разделе заказ ведёт в существующие контакты; гайд — только запрос на покупку. Платный PDF не хранится и публично не раздаётся.

Если OLNOO вернул пустой список, сайт показывает пустой каталог; при отсутствующей конфигурации/ошибке подключения показывает временную недоступность, без демонстрационных товаров и без технических подробностей.

Применить OLNOO PR и настроить серверные переменные существующим способом до приёмки сайта. Миграцию 0039 повторно не запускать (применена на KZ владельцем). Из этого PR не выполнялись merge, deploy, изменение серверных переменных или production. Живую цепочку с Basic Auth и фото нужно подтвердить после отдельно одобренного развёртывания.

Проверки: node --experimental-strip-types --test lib/*.test.ts scripts/*.test.mjs; tsc --noEmit; next build --webpack; git diff --check.

Для защиты от ошибочного ключа другого проекта сайт дополнительно требует `project: istraart` в DTO и заголовок `X-Olnoo-Catalog-Project: istraart` во всех ответах OLNOO, включая фото. URL-параметры посетителя не выбирают проект.

## Подключение при недоступном DNS admin.olnoo.com

По подтверждению владельца, домен olnoo.com не продлён, публичный DNS Admin
недоступен. Проверка с RU через `curl --resolve admin.olnoo.com:443:213.155.29.140`
возвращает 401 без авторизации: HTTPS endpoint и Basic Auth отвечают.

Серверный клиент каталога локально разрешает **только** HTTPS origin
`https://admin.olnoo.com` в `213.155.29.140:443`. Это применяется и к данным, и к
фотографиям. URL, Host и SNI остаются `admin.olnoo.com`; стандартная проверка
цепочки доверия, срока действия и имени сертификата включена. При ошибке TLS
запрос отклоняется, без перехода на HTTP, отключения TLS или другого адреса.
Сертификат должен оставаться действительным; фиксированный IP не решает его
будущее истечение и не заменяет продление домена/сертификата оператором.

Используется встроенный Node HTTPS с локальным lookup, без нового пакета,
глобального DNS override или общего HTTPS agent. Другие origin используют прежний
fetch. Две авторизации, запрет редиректов, таймаут 10 секунд, ограничения размера,
no-store и проверка проекта istraart сохранены. Изменений DNS, nginx, окружения,
OLNOO или production в этом PR нет. После восстановления DNS этот локальный pin
можно убрать отдельным изменением клиента.

Регрессионные тесты используют настоящий локальный HTTPS-сервер и временные
тестовые сертификаты (нужен openssl). Проверяют фиксированный адрес lookup,
Host/SNI, чтение каталога/фото, обе авторизации, отказ при недоверенном сертификате
и неверном имени, запрет редиректов, отказ чужому проекту и неизменность транспорта
для других доменов. Тестовый сокет направлен на loopback вместо production IP.
Живой запрос RU → KZ и чтение опубликованных карточек после deploy необходимо
проверить отдельно; локальные тесты не подтверждают текущее состояние production.


## Самостоятельные страницы и опубликованные связи (изменения репозитория)

Фактический контракт сверен с OLNOO PR #109, commit `a189f58`:
`lib/catalog-export.ts` / `GET /api/catalog/export`. Это контракт ветки PR;
развёртывание OLNOO этим изменением сайта не проверяется и не выполняется.

Каждая строка `cards` — самостоятельная опубликованная карточка со своими UUID,
slug и `offers`. Новые карточки содержат один `raw`, `finished` или `guide` offer;
старые legacy-карточки могут сохранять несколько offers. Поля прежнего DTO не
меняются. Дополнительное необязательное поле:

```json
{
  "relatedCards": [
    { "id": "00000000-0000-4000-8000-000000000001", "slug": "material", "title": "Исходный материал", "type": "raw" }
  ]
}
```

Сайт проверяет UUID, slug, тип и обязательные поля, затем сверяет каждую связь с
полной карточкой в текущем экспорте проекта istraart (UUID + slug + offer type).
Ссылка на отсутствующий/снятый с публикации/чужой товар исключается. Название для
ссылки берётся из проверенной полной карточки. Не вычисляются связи по догадкам,
имени изделия или общему изображению; источник связей — только OLNOO. Внутренние
ID исходников и parent_card_id сайт не запрашивает и не хранит. Цены — только
положительные целые RUB в допустимом диапазоне OLNOO; нужны описание, явная
доступность и непустые индексы фото. Некорректный DTO закрывает каталог с ошибкой,
без запасных демо-товаров или цен.

- Главная сохраняет сетку/фильтры/оформление; плитки ведут на `/catalog/<slug>`.
- Страница товара использует прежний вид галереи, описания, цены, доступности и
  заказа через `/#contacts`. Гайд предлагает только запрос покупки, без PDF.
- Изделие показывает опубликованные материал/гайд; материал — опубликованные
  изделия; гайд — опубликованные материал/изделие, согласно relatedCards.
- Legacy-карточка имеет одну собственную страницу и переключение только реально
  доступных предложений. Сайт не придумывает новые UUID/slug для старых offers.
- Неизвестный или отсутствующий в текущем экспорте slug — 404. Снятый с публикации
  товар исчезает при следующем серверном запросе. Ошибка OLNOO — временная ошибка
  загрузки, не фиктивная 404. Данные не сохраняются между запросами; React cache
  только устраняет повторный запрос metadata/page в рамках одного render.
- Ссылка по slug и canonical сформированы локально, а не из произвольного URL API.
  Добавлены sitemap.xml с текущими экспортированными карточками и robots.txt,
  исключающий /api/. Навигационные ссылки шапки/подвала ведут на секции главной
  также со страницы товара. Дизайн и геометрия логотипа сохранены.
- Фотографии остаются через существующий защищённый серверный proxy. OLNOO
  повторно проверяет публикацию/проект/выбранный индекс на каждый запрос. Нет
  прямых ссылок на Admin, uploads или PDF. При недоступности файла показывается
  нейтральное сообщение вместо сломанной/выдуманной фотографии.

HTTPS pin/SNI/Host, проверка сертификата, Basic Auth и project token не менялись.
Секреты не попадают в клиент, HTML, sitemap и ссылочные URL. Уже загруженные
публичные данные нельзя отозвать из браузера; права на последующие запросы фото
проверяются upstream заново, а ссылки карточек не prefetch-ятся.

Порядок отдельно одобренного выпуска: сначала OLNOO migration 0040 и PR #109 по
его инструкции, затем этот PR сайта. Сайт сохраняет совместимость с прежним
экспортом без relatedCards, но связи появятся только с новым OLNOO export.
Миграции сайта не нужны; 0039 повторно не запускать. Ни merge, ни deploy, ни
настройки production в рамках этой задачи не выполнялись.

Локальные проверки включают реальные функции parser/page/photo route и SSR
компонентов с изолированным upstream: все направления связей, ссылка на draft,
удаление опубликованной карточки из экспорта, чужой проект, неверный slug/тип,
непроверенная цена/отсутствующие индексы фото, legacy, статусы 404, фото MIME,
проверку обоих заголовков авторизации и project-header, no-store, sitemap.
Существующие TLS и доставки секретов тесты сохранены. Это тестовые данные;
живые карточки, RU→KZ и браузерная приёмка production не заявляются.

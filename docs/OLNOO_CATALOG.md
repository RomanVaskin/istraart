# Каталог IstraArt из OLNOO

Источник: существующая таблица catalog_cards в OLNOO, проект istraart. Сайт не имеет собственной БД или админки. Демо-товары/цены удалены из каталога, декоративные изображения других секций сохранены.

Страница получает опубликованный whitelist DTO серверным запросом к /api/catalog/export. Ключ чтения OLNOO привязан только к istraart. Две серверные переменные для авторизации: OLNOO_CATALOG_TOKEN (отдельный ключ чтения проекта, минимум 32 символа) и OLNOO_CATALOG_BASIC_AUTH (существующее имя:пароль внешней Basic Auth Admin). OLNOO_CATALOG_URL — HTTPS origin Admin, по умолчанию https://admin.olnoo.com. Ни одна переменная не NEXT_PUBLIC, секреты не попадают в HTML/клиентские props/фото URL. Не отключать Basic Auth и не открывать внутренние API.

Фото выдаёт только серверный proxy сайта /api/catalog/photos/<cardUUID>/<originalIndex>. OLNOO на каждом запросе проверяет публикацию, проект ключа и то, что индекс используется опубликованным предложением. Нет произвольного upstream URL, доступа к оригинальным item id, путям uploads, черновикам или PDF. Данные и фото используют no-store; изменение цены/выбора фото обновляет ту же карточку при следующей загрузке страницы. Снятая с публикации карточка/фото перестают выдаваться; уже полученное посетителем публичное содержимое отозвать невозможно.

Одна находка содержит независимые предложения Материал/raw, Готовое изделие/finished, Гайд/guide. Отсутствующие предложения не получают выдуманной цены/наличия. В физическом разделе заказ ведёт в существующие контакты; гайд — только запрос на покупку. Платный PDF не хранится и публично не раздаётся.

Если OLNOO вернул пустой список, сайт показывает пустой каталог; при отсутствующей конфигурации/ошибке подключения показывает временную недоступность, без демонстрационных товаров и без технических подробностей.

Применить OLNOO PR и настроить серверные переменные существующим способом до приёмки сайта. Миграцию 0039 повторно не запускать (применена на KZ владельцем). Из этого PR не выполнялись merge, deploy, изменение серверных переменных или production. Живую цепочку с Basic Auth и фото нужно подтвердить после отдельно одобренного развёртывания.

Проверки: node --experimental-strip-types --test lib/olnoo-catalog.test.ts; tsc --noEmit; next build --webpack; git diff --check.

Для защиты от ошибочного ключа другого проекта сайт дополнительно требует `project: istraart` в DTO и заголовок `X-Olnoo-Catalog-Project: istraart` во всех ответах OLNOO, включая фото. URL-параметры посетителя не выбирают проект.
